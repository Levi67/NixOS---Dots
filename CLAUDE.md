## Build & rebuild

```bash
./update.sh                                       # nix flake update + rebuild switch
sudo nixos-rebuild switch --flake .#nixie         # rebuild without updating inputs
sudo nixos-rebuild test   --flake .#nixie         # try config without making it default boot
sudo nixos-rebuild build  --flake .#nixie         # dry build only
nix flake check                                   # evaluate the flake
```

Hostname is `nixie` — every rebuild targets `.#nixie`. The system auto-upgrades weekly against `git+file:///home/levi/nixos-dotfiles#nixie`, so committing broken changes to this working tree will break the next background upgrade.

Submodules (`config/nvim`, `config/qtile`) live in separate repos — after cloning, run `git submodule update --init --recursive`.

## Architecture

This is a single-host flake. Everything hangs off `flake.nix → nixosConfigurations.nixie`, which composes:

- `configuration.nix` — hardware-adjacent system config (bootloader, kernel params, NVIDIA/PRIME, networking, firewall, user `levi`, auto-upgrade). Also imports `hardware-configuration.nix` (autogenerated, don't edit) and `modules/shared/flatpak.nix`.
- `modules/common/default.nix` — the "core desktop" module. Contains the **home-manager block for user `levi`** (which imports `home.nix` and `modules/shared/hyprland.nix`), Spicetify config, cursor theme, and most desktop system packages.
- `modules/shared/{gaming,developing,recording}.nix` — opt-in feature bundles imported directly from `flake.nix`. Each mixes system-level config with a `home-manager.users.levi = { ... }` block, so a "feature" typically spans both layers in one file.
- `modules/services/{jellyfin,wallust-poller}.nix` — long-running services. `wallust-poller` is a **user systemd unit** that runs `~/.config/scripts/swww-wallust-executer.sh` under `graphical-session.target`.

### Two ways this repo splits system vs. user config

1. **NixOS modules** under `modules/` are evaluated at system rebuild.
2. **home-manager** is embedded — there is no separate `home-manager switch`. User config is applied by the same `nixos-rebuild switch`. `home.nix` is the primary home-manager entry point and is imported by `modules/common/default.nix`. `backupFileExtension = "backup"` is set in the flake, so conflicting pre-existing dotfiles get renamed rather than causing a rebuild failure.

### Dotfile symlink pattern (important)

`home.nix` and `modules/shared/hyprland.nix` symlink configs from `~/nixos-dotfiles/config/*` into `~/.config/*` using `config.lib.file.mkOutOfStoreSymlink`. This means **edits to files under `config/` take effect immediately without a rebuild** — the symlinks point at the live repo, not the Nix store. Adding a *new* top-level config directory still requires editing `home.nix`/`hyprland.nix` and rebuilding.

`config/hypr/monitors.conf` is gitignored — it's host-specific and generated by `nwg-displays`.

### The `myHyprland` option

`modules/shared/hyprland.nix` defines a custom option namespace (`options.myHyprland.enable`, `.wallpaperEngine`) rather than applying config unconditionally. It's turned on in `home.nix` via `myHyprland.enable = true;`. When adding Hyprland-adjacent packages or symlinks, put them inside the `config = lib.mkIf cfg.enable { ... }` block so they stay gated by that toggle.

## Hardware constraints worth knowing

- NVIDIA 40-series in **PRIME sync mode** with `hardware.nvidia.open = true`. `powerManagement.enable = false` is intentional — the `NVreg_RegistryDwords` kernel param pins the card into a high power state to avoid stutter. Don't "clean up" these together.
- Several kernel params in `configuration.nix` are game-specific workarounds (`vsyscall=emulate` for PioneerGame, `clearcpuid=514` disables UMIP, `split_lock_detect=off` for GameMode). Preserve them unless you know why they're there.
- Firewall opens `8096`/`8920` TCP and `1900`/`7359` UDP — Jellyfin + DLNA.

## Conventions

- Comments in Nix files are frequently in German — that's fine, don't translate them.
- `nixpkgs` tracks `nixos-25.11`; home-manager tracks `release-25.11`. Keep them in lockstep when bumping.
- `nixpkgs.config.permittedInsecurePackages` in `configuration.nix` lists specific Electron versions — extend the list rather than removing entries unless you've confirmed nothing still needs them.
